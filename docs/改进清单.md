# AI需求分析系统 - 改进清单

> 整理日期: 2026-04-23

---

## 1. 历史需求查看与管理

| 项 | 说明 |
|---|---|
| **功能** | 能够查看历史需求及对应的分析结果 |
| **存储方式** | 前端 localStorage / IndexedDB（纯本地，无需后端改动） |
| **界面** | 侧边栏或顶部下拉菜单，列出历史需求标题+时间 |
| **操作** | 点击历史项加载完整结果、删除单条、清空全部 |
| **数据量** | 建议限制存储数量（如最近50条）或总大小 |

---

## 2. 过程与结果的视图切换

| 项 | 说明 |
|---|---|
| **当前问题** | 分析过程中显示过程，结果出来后过程和结果堆叠显示，占用空间 |
| **改进方案** | 结果完成后，过程面板收起，顶部出现"过程"/"结果"两个标签页或菜单按钮切换 |
| **默认视图** | 结果完成后默认显示"结果"页 |
| **过程页保留** | 用户可随时切回查看各步骤的详细进度 |

---

## 3. 面板折叠功能

| 项 | 说明 |
|---|---|
| **功能** | 各结果面板（需求理解、需求分析、输出生成）支持通过标题栏折叠/展开 |
| **交互** | 点击标题栏右侧的 ▼/▶ 图标切换 |
| **默认状态** | 结果刚出来时全部展开；用户折叠后状态可记忆（可选） |
| **适用面板** | UnderstandingResult、AnalysisResult、OutputResult 三个组件 |

---

## 4. 澄清问题交互 + 本地保存

### 4A. 澄清问题前置交互（流程改动）

| 项 | 说明 |
|---|---|
| **当前流程** | 需求 → 一次性完整分析（3次LLM调用）→ 结果 |
| **新流程选项** | 需求 → Layer 2需求理解 → **弹出澄清问题** → 用户回答 → 带着澄清答案继续Layer 3+4分析 |
| **界面** | Layer 2完成后，前端显示澄清问题列表（选择题/输入框），用户填写后点击"继续分析" |
| **后端改动** | 需要拆分接口：先调 `/understand` 获取澄清问题，再调 `/analyze` 传入澄清答案 |
| **优势** | 分析更精准，减少LLM猜测 |

### 4B. 分析结果本地保存（数据持久化）

| 项 | 说明 |
|---|---|
| **保存时机** | 每次分析完成后自动保存到浏览器本地存储 |
| **保存内容** | 完整结果（understanding + analysis + output + 原始需求 + 时间戳） |
| **用途1** | 支持"改进"——基于已有分析重新编辑需求再次分析 |
| **用途2** | 支持历史查看（与需求1合并） |
| **数据格式** | 建议给每次分析生成唯一ID，方便后续引用 |

## 优先级建议

```
P0（建议先做，简单且影响大）
  ├── 3. 面板折叠（纯前端UI改动，无依赖）
  └── 2. 过程/结果切换（纯前端UI改动，依赖流式已完成）

P1（需要设计交互流程）
  ├── 1. 历史查看（需要确定存储方案）
  └── 4B. 本地保存（和历史查看共用存储层）

P2（涉及流程重构，改动较大）
  └── 4A. 澄清问题前置交互（需要改后端流程+前端交互）
```

---

## 待确认问题

1. **澄清问题的交互方式**：用户是必须在回答澄清问题后才能继续，还是可以跳过直接看结果？
2. **保存范围**：是只保存最终结果，还是中间各层的结果也保存？
3. **历史查看的入口位置**：侧边栏抽屉？顶部导航？还是单独页面？
4. **"改进"的具体操作**：是基于已有分析修改原始需求重新分析，还是在已有结果上追加编辑？
